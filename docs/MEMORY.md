# Project Memory

- Donate boxes (`#jBnskDj9`) are siblings after each post, not inside it, so `hidePostRule` hides them with the post. The site itself hides them on the main page and search results, so test on tag, category or date lists. Infinite scroll brings each post's box along with it, and the site's CSS still applies, so they stay hidden on those two pages. The site's boxes matter to the user: never hide one unless its post is hidden.
- The filter's tag list is saved as `filterTagCache` with a `savedAt` time. It shows immediately, and a copy older than 24 hours refreshes in the background, so a brand-new tag can take up to a day to appear. The Tags page still fetches live.
- Tag filters live only in memory and clear on every page load. The script's own reload after discarding posts passes them through the one-time `fg-filters` sessionStorage key, which test scripts also use to start with a filter. Installs that used filters before this may have old unused `filterInclude` and `filterExclude` values saved; they're ignored.
- With infinite scroll on, the page bar is collapsed, not `display: none`, because `loadIfNearEnd` measures the `a.next` link's position and a hidden link reads as 0, which would fetch forever. Use `nav.paging-navigation` to find it: `nav.navigation` also matches the sidebar menu and single-post navigation.
- The tag filter relies on WordPress putting `tag-<slug>` classes on each `article`. It only runs where `body` has `home`, `archive` or `search`. Popular Repacks and All My Repacks, A-Z are single pages of plain links with no per-game tag data, so it can't filter them. Live updates use the element `GM_addStyle` returns, and fall back to reloading if a script manager returns nothing. Infinite scroll throws away fetched posts that a filter or hide setting would hide, because keeping them made the page very slow, so changing a filter after that reloads the page. It waits 1 second after a page with no matches and pauses after 20 in a row until the reader scrolls, so a rare tag can't crawl the whole site. `scripts/filter-check.js` and `scripts/filter-scroll-check.js` cover this.
- New features should use `whenEnabled` and get an entry in `settings`. Settings are stored per setting name with `GM_getValue`, so renaming a key resets it for users. The Tampermonkey menu and the page panel both build from `settings`, so a new entry shows up in both. The panel's CSS sits outside the theme so it stays readable with the theme off. `scripts/settings-check.js` tests each toggle and the panel.
- The script runs at `document-start` so the theme beats the first paint. Anything touching page content must go through `whenDomReady`. Don't bring jQuery back: it crashed on load when run before the page had a root element, which stopped the whole script in the early-start test. `scripts/flash-check.js` covers this path.
- `recolorImage` edits the site's images in a canvas, which works because they're on the same domain as the page. Its values are tuned to the current files: `paw.png` is flat `#fddbff` on white, and the white strip in `support2.jpg` starts at pixel row 124. If either file's design changes, these need retuning.
- `scripts/live-check.js` skips trailer popups unless `CHECK_TRAILERS` is turned on.
- Light images can go dark without a new file: `background-blend-mode: multiply` over a radial gradient that ends inside the box fades them into the page. Use it rather than `filter` when text sits inside the same element. `replaceImages` applies this to `garold` images from JavaScript so it can reuse the page's image URL, and the `fg-garold` class stops it stacking when infinite scroll reruns the function.
- Installed copies update from Greasy Fork (script 541076), so pushing to GitHub alone may not reach them. Check that the Greasy Fork version matches before choosing the next version number.
- Greasy Fork sync depends on the raw GitHub URL of `FitGirl Power Pack.user.js`, so don't rename that file or put the version back in its name. Bump `@version` on every release.
- Don't rely on DuckDuckGo `!` bang redirects: one went straight to YouTube in a test browser, but the user got a search page. Trailers now read the first `videoRenderer` ID from YouTube's search HTML, and that markup could change.
- YouTube's top result isn't always the base game's trailer; it can be a season, expansion or console edition trailer.
- Paw images inside posts are rare: of the listing pages sampled on 2026-11-01, only `/page/50/` had one. Test infinite scroll from `/page/49/`.
- The site's tags API returned 314 tags over 4 pages on 2026-11-01.
- `scripts/live-check.js` tests against the live site through Playwright, injecting the script with `GM_addStyle` and `GM_xmlhttpRequest` shims. It doesn't cover Tampermonkey itself. Its shim loads YouTube in a real tab because `page.request` fails on the large response headers.
